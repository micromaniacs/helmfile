## Image design decisions (not recorded elsewhere)

- Final base image: the official `ghcr.io/helmfile/helmfile:v<version>` (pinned to the latest helmfile release, resolved by the generator from the GitHub API) — chosen after hand-mounting the helm-diff plugin broke at runtime: the plugin archive wraps its content in a `diff/` directory, which helm's one-level plugin glob missed, so `helm diff` failed with "unknown command diff for helm". The base is alpine-based and ships helmfile, helm, helm-diff and the other plugins correctly installed, plus its own helm env (`HOME=/helm`, `HELM_DATA_HOME`, …) — we no longer set helm ENV or download/assemble helm/helm-diff ourselves
- Our layers on top: (1) kubectl latest stable from dl.k8s.io, overriding the base's older upstream-pinned kubectl at `/usr/local/bin/kubectl` — the builder stage detects its architecture at build time via `uname -m` (x86_64→amd64, aarch64→arm64), not `ARG TARGETARCH` (classic docker builders don't populate automatic platform args); (2) Node.js delivered multi-stage from `docker.io/library/node:<version>-alpine` (musl binary) — COPY of the node binary + node_modules, then npm/npx symlinks recreated with `ln -sf` (Docker COPY dereferences symlinks, which silently broke `npm` with "Cannot find module ../lib/cli.js"); the final stage runs `apk add --no-cache libstdc++`. Ships node+npm+npx only — no corepack (dropped from the Node.js ≥ 25 distribution)
- Node version = semver-max of exact `<X.Y.Z>-alpine` tags from the Docker Hub tag API (`hub.docker.com/v2/repositories/library/node/tags/?name=alpine`) that have both `linux/amd64` and `linux/arm64` images, resolved in `internal/fetcher` like the other tools. The `?name=alpine` filter is required: Hub orders tags by last push, and the crowd of named alias tags (`lts-*`, `krypton-*`, `current-*`, …) pushed exact `X.Y.Z-alpine` tags off the first 100-result page, which broke the resolver ("no multi-arch node tag found"). Not the nodejs.org dist index: docker-node images lag nodejs.org releases by ~1.5–2 days (arm64 is built from source), which would break the daily 03:00 UTC cron; resolving from Docker Hub guarantees the pinned tag exists multi-arch at build time
- Tool versions (kubectl/helmfile/node/alpine): latest stable resolved at generation time from dl.k8s.io (kubectl), the GitHub API (helmfile → base image tag), the Docker Hub tag API (node) and the dl-cdn.alpinelinux.org directory index (alpine, builder stage), no pinning
- Builder stage (alpine) only downloads kubectl
- Dockerfile template at `assets/Dockerfile.template`, embedded via the `assets` package (`assets/assets.go`) and rendered by `cmd/image` into the gitignored root `Dockerfile`
- Build & publish: `.github/workflows/docker.yml` builds the multi-arch image (daily 03:00 UTC + manual), pushes it to GHCR as `latest` + the bundled helmfile version tag, then smoke-tests the pushed `:latest` (`helmfile version && helm version && helm diff version && kubectl version --client && node --version && npm --version`), then deletes untagged GHCR image versions (`dataaxiom/ghcr-cleanup-action`)

## Commands

Always work with code through Makefile targets — never invoke `go` or
`golangci-lint` directly.

Run in this order when changing code: `make mod` → `make fmt` → `make lint` → `make test`.

- `make` — show help (all targets)
- `make build` — build binary `image` from `./cmd/image` into `./build` (gitignored)
- `make run` — run the app
- `make generate` — run the generator to write the root `Dockerfile`
- `make image` — generate the Dockerfile, then `docker build -t ghcr.io/alexeyco/helmfile:local .`
- `make mock` — regenerate gomock mocks (`internal/fetcher/deps_test.go`, driven by `go:generate` in `deps.go`)
- Formatting and linting use golangci-lint v2+ (`golangci-lint fmt` / `golangci-lint run`); config: `.golangci.yml` (default linters)

## Current state

Module deps: `github.com/spf13/afero` (FS abstraction) and `go.uber.org/mock`
(as a `tool` dependency for mockgen). `assets` package embeds
`assets/Dockerfile.template`; `internal/versions.go` (package `internal`) holds
the shared `Versions` struct; `internal/fetcher` — `Fetcher` struct built via
`New(HTTPClient)` (interface in `deps.go`, mocks generated by `make mock`),
resolves all four tool versions in parallel; `internal/generate` — `Generator`
struct over `afero.Fs` with `Generate(v, path)` (tests use `afero.MemMapFs`);
`cmd/image` generator CLI (fetches versions and writes the root `Dockerfile`;
CI extracts the helmfile version tag from it); `make generate` target.
`.github/workflows/docker.yml` (daily 03:00 UTC + manual) builds the
multi-arch image, pushes it to GHCR as `latest` + helmfile version tag, then
smoke-tests the pushed `:latest` (`helmfile version && helm version &&
helm diff version && kubectl version --client && node --version`) and
deletes untagged GHCR image versions.
Generated root `Dockerfile` is gitignored.
